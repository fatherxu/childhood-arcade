# 开发指南

本文覆盖仓库结构、构建、部署命令、校验模型和发布流程。完整架构与类级别说明见[CodeWiki](CodeWiki.md)，终端用户操作见[使用指南](使用指南.md)。

## 仓库结构

```text
childhood-arcade/
├── README.md                     # 项目入口
├── docs/                         # 使用指南、开发指南、CodeWiki
├── skills/childhood-arcade-tv/   # 电脑端部署 Skill
│   ├── SKILL.md                  # 智能体操作指令
│   ├── assets/release.json       # 固定版本、文件名、SHA-256、传输协议
│   ├── references/operations.md  # 正式版操作细则
│   ├── scripts/                  # 部署脚本（入口 tv.py）
│   └── tests/                    # 31 项 unittest
└── source/                       # Android 应用代码审阅副本
    ├── app/src/main/             # Java、assets、res、Manifest
    ├── app/libs/jna-5.13.0.jar
    ├── scripts/build-production.py
    ├── scripts/check-native-abis.py
    ├── release-catalog.json      # 仓库内为空占位，发布构建需替换
    ├── native-abi-lock.json      # 两个 ARM ABI 的原生库哈希锁
    ├── third_party/              # 内核源码归档
    └── licenses/
```

本仓库是代码审阅副本，以下构建输入未纳入版本库：`app/src/main/jniLibs/`（预编译原生内核）、`assets/fonts/`、各平台 `player.html`、前端开发脚本 `scripts/serve.cjs` 与前端 `tests/`。`release-catalog.json` 在仓库内为 `[]` 占位，直接构建只会得到空游戏目录。

## 环境要求

- JDK 17 及以上（GitHub 发布工作流使用 JDK 21）。
- Android SDK build-tools：`aapt2`、`d8`、`zipalign`、`apksigner`。
- `android.jar`（API 35 或更高）。
- Python 3.9+，只使用标准库。
- 构建还需可用的 `app/src/main/jniLibs/`。可从 Release 的 `childhood-arcade-build-inputs-1.0.0.zip` 解压到 `source/app/src/main/` 获取；该包不含签名密钥、ROM 和第三方源码归档。

## 构建 APK

在仓库根目录执行：

```sh
python3 source/scripts/build-production.py \
  --jdk /path/to/jdk \
  --tools /path/to/android-sdk/build-tools/<版本> \
  --android-jar /path/to/android-35/android.jar \
  --signing-config /仓库外/signing.json
```

Windows 使用实际解释器，例如：

```powershell
py -3 source/scripts/build-production.py --jdk "D:\jdk" --tools "D:\android-sdk\build-tools\37.0.0" --android-jar "D:\android-sdk\platforms\android-35\android.jar" --signing-config "D:\keys\signing.json"
```

构建脚本会：

1. 运行 `check-native-abis.py`，核对 `armeabi-v7a` / `arm64-v8a` 的库集合、ELF 架构与 SHA-256。
2. 复制 assets，移除 iframe 播放器目录，由 `release-catalog.json` 生成 `catalog.js`。
3. 用 aapt2 编译与链接资源，并从 `version.json` 注入版本号。
4. 用 javac（`-source 8 -target 8`）编译，d8 生成 `classes.dex`。
5. 只打包 `native-abi-lock.json` 锁定的两个 ARM ABI，zipalign 后签名并校验。
6. 输出 APK；当传入 `--version-code` 时同时生成 `build-production/update.json`。

`version.json` 是 APK 版本的唯一来源。需要临时覆盖时传 `--version`、`--version-name` 或 `--version-code`。

### 签名配置

`--signing-config` 指向仓库外的 JSON：

```json
{ "keystore": "/绝对路径/release.jks", "alias": "release", "password": "******" }
```

签名材料属于机密，不放入仓库、Release、截图或日志。密码只通过子进程环境变量传给签名工具。用自己的密钥构建的版本不能覆盖原发行签名版本。

### 应用内更新清单

`update.json` 包含 `versionCode`、`versionName`、APK 的 URL/大小/SHA-256，以及可选的 `resources` 资源包块。应用通过：

```text
https://github.com/fatherxu/childhood-arcade/releases/latest/download/update.json
```

检查更新，并校验 APK 的包名、版本、SHA-256 与签名。资源包地址由 `release.json` 的 `game_pack` 生成。

## 部署命令

在 `skills/childhood-arcade-tv` 目录执行，`scripts/` 使用同目录平铺导入：

```sh
# 下载指定仓库的正式发布并部署
python3 scripts/setup_release.py --repo fatherxu/childhood-arcade --serial 电视IP

# 本地 APK + 资源包
python3 scripts/tv.py configure --apk /绝对路径/app.apk --sha256 APK的SHA256 --game-pack-manifest /绝对路径/game-pack/manifest.json --transport provider
python3 scripts/tv.py deploy --serial 电视IP
python3 scripts/tv.py status
python3 scripts/tv.py doctor --serial 电视IP

# 备份与恢复
python3 scripts/tv.py backup --serial 电视IP --output /绝对路径/backup.json
python3 scripts/tv.py restore --serial 电视IP --input /绝对路径/backup.zip
```

省略 `--serial` 时，`status` 只读本地配置；`doctor`、`backup`、`restore` 会回退到待授权地址或已绑定目标。脚本不会扫描网络或自动选择设备。结果以 JSON 输出，状态码与处理策略见 [CodeWiki 第 12 节](CodeWiki.md#12-状态码与错误处理)。

## 校验与权限

部署链路中的 SHA-256 依次覆盖：`release.json` 固定值 → HTTPS 下载 → APK 结构 → 资源包 ZIP → 逐文件安装 → 设备端白名单与二次哈希 → ROM 载入前校验 → 页面健康状态。

- 下载强制 HTTPS，重定向也必须是 HTTPS，单文件上限 2 GiB。
- 解包拒绝绝对路径、`..`、反斜杠、符号链接、重复项，限制 2 GiB / 5000 个文件。
- 正式版关闭 APK 与 WebView 调试。资源传输走 `DeploymentProvider`，要求 `android.permission.DUMP` 且调用 UID 为 shell/root；只提供 `verify`、`install`、`restore`、`health`、`capabilities`。
- 应用内更新只通过 `UpdateProvider` 向系统安装器暴露已校验的单个 APK。
- APK 的 `INTERNET` 权限只用于应用内更新和资源下载；WebView 仍拦截所有 `http(s)` 请求，只加载本地资源。

完整性校验不能单独证明来源可信、内容安全或设备兼容。页面可见也不代表声音、性能、实体手柄通过。

## 测试

```sh
cd skills/childhood-arcade-tv
python3 -m unittest discover -s tests -v
```

当前 31 项测试，覆盖设备身份、签名冲突不卸载、空间检查、备份顺序、资源篡改、路径穿越、provider 结果解析等安全关键路径。前端脚本可用 Node.js 做语法检查：

```sh
node --check source/app/src/main/assets/app.js
```

前端预览脚本 `scripts/serve.cjs` 与浏览器测试不在仓库中，需从构建输入补齐。

## 发布流程

1. 更新 `source/version.json` 的 `versionName` / `versionCode`。
2. 更新 `skills/childhood-arcade-tv/assets/release.json` 的 `tag`、文件名、字节数和 SHA-256。
3. 如需更新游戏目录，替换 `source/release-catalog.json` 并同步资源清单。
4. 运行测试，构建并签名 APK，生成 `update.json`。
5. 推送 `v*` 标签。`.github/workflows/release.yml` 会构建、校验版本、创建 Release 并上传 APK 与 `update.json`，同时标记为 latest。
6. 若发布资源包，另建对应标签并上传 `childhood-arcade-games-<版本>.zip`；`release.json` 的 `game_pack` 必须指向实际存在的附件。
7. 生成并核对 `SHA256SUMS.txt`。

发布前检查清单见 [CodeWiki 16.7](CodeWiki.md#167-发布检查清单)。签名密钥必须与上一版一致；轮换会导致老用户必须卸载才能安装。

## 代码约定

- Java：`-source 8 -target 8`，`minSdk 23`，不使用 Gradle。
- 前端：ES5 语法、无构建步骤、不引入运行时 CDN；新增动作同时更新 `action()` 与 `uiKey()`。
- Python：仅标准库，异常收敛为 `DeploymentError`。
- 原生库：只打包 `armeabi-v7a` / `arm64-v8a`；新增内核需记录来源、许可证和哈希。
- 不提交 keystore、密码、Token、构建产物或 ROM。
